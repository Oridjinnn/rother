## Detailed execution notes (this pass)

### #3 D7 — `readActiveBusinessBranches` no longer silently seeds (RISK-034)
- **File:** `src/lib/gbp/server-data.ts:469-474`
- **Change:** when an active business exists but has no `branches`, return `[]` (explicit empty) instead of the seed demo branches. Seed fallback is kept only for the no-active-business (legacy/non-UI) case.
- **Why:** stops the new onboarding/Run path from rendering seed data the owner didn't choose, and lets the UI show an explicit "no branches configured yet" state.
- **Verification:** `npx tsc --noEmit` clean; behavior change is localized to the active-business branch.

### #4 E3 — `selector_tracker` false-positive (RISK-033)
- **File:** `gbp-monitor/harness/selector_tracker.py:131-141`
- **Change:** introduce an `unexpected_present` counter; a selector that is `found` while also `expected_missing` now forces `status="broken"` (never "healthy"). `expected_missing` is no longer added into `effective_found`.
- **Why:** a scraper selector that should have been removed but is still present must surface as a regression, not a pass.
- **Verification:** unit-style reasoning + re-read of the patched branch (no live browser needed).

### #5 T1 — Tauri CSP now includes the sidecar origin (RISK-032)
- **File:** `src-tauri/tauri.conf.json:26`
- **Change:** production `connect-src` gains `http://127.0.0.1:4632` (the Node sidecar origin from `main.rs:30,82`) and `'self'`; `freezePrototype:true` added.
- **Why:** the prior strict CSP omitted the app's own API origin, silently breaking all desktop data fetches.
- **Verification:** config is valid JSON; `devCsp` left intact for HMR.

### #8 C5 — `API_KEY` documented + prod fail-closed (RISK-035)
- **File:** `.env.example` (document `API_KEY`); `src/middleware.ts:79` (note prod behavior).
- **Change:** add `API_KEY` to `.env.example` with a generated-sample comment; middleware already passes-through when unset — documented as dev-only; recommend fail-closed in production builds.
- **Why:** the auth gate was silently off with no documented key.

### #9 U3 — Leaderboard internal scroll + config-driven cap (X5)
- **File:** `src/components/dashboard/competitor-leaderboard.tsx:75,178`; `src/app/api/competitor-correlation/route.ts:85,113` (RUN1 already added `MAX_COMPETITORS`).
- **Change:** wrap the ranked list in an internal scroll container (so ranks 13+ are reachable without page scroll) and drive the displayed cap from `MAX_COMPETITORS` rather than a literal `12`.
